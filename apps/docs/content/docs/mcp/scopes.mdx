MCP clients obtain tokens from **`apps/auth`** (Better Auth OAuth 2.1 + MCP plugin). Scopes are coarse-grained; each tool still checks the canonical action at runtime.

## Scope reference

| Scope | Grants access to |
| --- | --- |
| `organizations:read` | Organization metadata, teams, invitations (read) |
| `projects:read` | Projects and environments (read) |
| `variables:read` | Variable metadata without secret values |
| `variables:reveal` | Decrypt and return secret values |
| `variables:write` | Create, update, delete variables |
| `variables:export` | Bulk export flows |
| `audit:read` | Timeline / audit events |
| `notifications:read` | In-app notifications |
| `account:read` | Self-scoped account operations (not exposed as MCP tools) |
| `platform:admin` | Platform operator APIs (console only — **not** MCP) |

## Public documentation

All scope and tool documentation is **public** — knowing a scope name does not grant access without a valid token and passing `requireAction` checks.

## Auth & studio links

- **Sign in** — configure `NEXT_PUBLIC_AUTH_URL` (phase 1: `https://auth-env-manager.vercel.app`)
- **Studio** — configure `NEXT_PUBLIC_STUDIO_URL` (phase 1: current web dashboard URL)
